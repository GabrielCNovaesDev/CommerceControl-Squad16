# Plano: Geração em Lote de Usuários por Squad

## Objetivo

Permitir que o admin (GAME_MASTER) gere automaticamente os logins (email + senha) de todos os jogadores de um squad com um único clique, sem precisar criar cada usuário manualmente.

---

## Regras de Negócio

- O botão de geração fica dentro do painel expandido de cada squad na página **SquadsManagementPage**.
- O admin informa **quantos jogadores** quer gerar para aquele squad.
- O sistema gera os usuários com:
  - **Nome**: `Jogador 1`, `Jogador 2`, ..., `Jogador N`
  - **Email**: `jogador1@<nomeloja>.com`, `jogador2@<nomeloja>.com`, ...
    - O nome da loja é obtido de `squad.stores[0].name`, normalizado (sem espaços, sem acentos, minúsculas).
    - Se o squad não tiver loja vinculada, usa o nome do squad normalizado como domínio.
  - **Senha**: `jogador123` (fixa para todos)
  - **Role**: `PLAYER`
  - **squadId**: o id do squad em questão
- A numeração começa em 1 e é sequencial. Se já existirem jogadores no squad, a numeração continua a partir do maior número existente (ex: já tem Jogador 1 e Jogador 2 → próximo é Jogador 3).
- Após a geração, o modal exibe um resumo com os emails e a senha gerados, para o admin copiar/anotar.
- Erros parciais (ex: email já em uso) são exibidos no resumo sem interromper os demais.

---

## Arquitetura

### Backend

**Novo endpoint**: `POST /users/bulk`

- Protegido por `authMiddleware` + `roleMiddleware(['GAME_MASTER'])` (mesma proteção de `/users`).
- Recebe no body:
  ```json
  {
    "squadId": "uuid",
    "count": 3
  }
  ```
- Lógica no controller:
  1. Valida `squadId` (uuid) e `count` (inteiro 1–50).
  2. Busca o squad com sua loja (`squad.stores[0]`) para montar o domínio do email.
  3. Conta quantos usuários com nome no padrão `Jogador N` já existem no squad para determinar o próximo índice.
  4. Para cada usuário a criar:
     - Monta nome: `Jogador {i}`
     - Monta email: `jogador{i}@{dominioNormalizado}.com`
     - Verifica se email já existe; se sim, registra erro e pula.
     - Cria o usuário com senha `jogador123` (hasheada com bcrypt).
  5. Retorna lista de resultados: `{ created: UserRecord[], errors: { index, email, reason }[] }`.

## Detalhes de Implementação

### Normalização do nome da loja para email
```
"Mercado Alpha" → "mercadoalpha"
"Loja São Paulo" → "lojasaopaulo"
```
Função utilitária: remover acentos (normalize NFD + replace), lowercase, remover caracteres não-alfanuméricos.

### Determinação do próximo índice
O backend faz uma query para contar usuários do squad cujo nome bate com o padrão `Jogador \d+`, e usa `max(índice) + 1` como ponto de partida.

### Exibição do resultado no modal
```
✓ jogador1@mercadoalpha.com  — criado
✓ jogador2@mercadoalpha.com  — criado
✗ jogador3@mercadoalpha.com  — email já em uso
Senha padrão: jogador123
```
